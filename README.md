# Quantura forecast workers

Minimal on-demand execution runtime for Quantura. Application and research sources live in a separate repository with independently managed visibility. Customer requests remain private.

Only repository maintainers can dispatch jobs. Dispatch inputs contain an opaque request ID. The worker claims its private input over an authenticated HTTPS callback, reports startup before dependency installation, runs the approved immutable model configuration, and returns results to Quantura. Customer inputs, model logs, and downloaded checkpoints are never published as artifacts or caches. Temporary inputs are removed when the job finishes.

Scheduled stock, game, and perpetual screeners publish validated public market snapshots with bounded retention and zero Firestore screener writes. A separate read-only game paper portfolio checks completed-hour P01 signals twice hourly and checkpoints its cumulative ledger in GitHub artifacts. It makes no live orders and holds no exchange credentials. Quote-proxy fills and modeled fees are research estimates. Unknown cross-venue game identities are skipped. No live trading workers are included. Standard public Ubuntu runners execute the forecasts; paid larger runners are not configured. Cancellation fences the saved request before requesting cancellation of its exact GitHub run.

The forward sports limit paper worker observes current order books, fixes its buy limit at the current ask minus one cent within ten cents below hourly P01, and expires unfilled orders at the next hour. Strict-through, depth-limited proxy fills are distinguished from actual exchange fills; price touches alone never count. Its source-only live broker adapter is excluded from this export. Paper state and reports use separate cumulative artifacts; no exchange credentials or cloud database writes are needed. Scheduled runner handoffs can miss decision windows, which are reported and never backfilled as trades.

Two additional independent hourly quote-replay portfolios compare the signaled side within ten cents below completed-hour P01 with the opposite side when the original ask is more than ten cents below P01. Both require optimized seven-model forecasts published before the hour, use one dollar principal plus modeled fees, respect published quantity increments and hold to official settlement. They start at their own future activation hour without importing retrospective trades. The paper statistics artifact contains comparison-stats.json and comparison-ledger.csv alongside the legacy reports. These are next-minute ask proxies, not passive-limit or live exchange fills.

Hourly metered-usage delivery calls the authenticated production billing endpoint using its own narrowly scoped credential. It logs aggregate counters only and does not publish customer data. Private-repository runners are not needed for this schedule.
Existing backend maintenance schedules also run here with a separate credential limited to their allowlisted server jobs. Credentials cannot authorize customer API calls or live exchange orders. Raw server responses are never published in logs.

Runtime updates are exported using the private application's `scripts/export_forecast_runtime.py` allowlist. `runtime-manifest.json` records source commit and file checksums.

The approved Quantura Metaculus bot polls eligible competitions every 15 minutes and forecasts on an offset 15-minute schedule. It starts in dry-run mode pending the owner’s readiness-report review. Verified time-series questions require all seven pinned production models and chronological weight optimization. Other questions use verified free OpenRouter models. Notes are private, duplicate forecasts are reconciled against Metaculus, and pending answers are encrypted in short-lived recovery artifacts. API credentials live only in Actions Secrets. See `docs/metaculus-bot.md` for setup and limits.
